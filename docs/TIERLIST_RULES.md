# CPVP.PRO TierList rules

## Назначение

TierList должна быть понятной, проверяемой и устойчивой к случайным изменениям. Этот документ фиксирует первую версию правил для будущего запуска.

## Категории

Минимальный набор категорий:

- Overall;
- Crystal;
- Sword;
- UHC;
- SMP.

Перед публичным запуском список категорий можно сократить или расширить.

## Уровни

Базовая шкала:

```text
HT1
LT1
HT2
LT2
HT3
LT3
```

Где `HT` означает верхнюю часть уровня, а `LT` — нижнюю часть уровня.

## Карточка рейтинга

Для каждой записи TierList отображаются:

- игрок;
- категория;
- текущий уровень;
- дата обновления;
- статус проверки;
- краткая причина изменения;
- история изменений.

## Статусы

```text
pending
in_review
verified
rejected
```

## Принципы проверки

1. Изменения должны иметь понятную причину.
2. Решение должно сохраняться в истории.
3. Категории оцениваются отдельно.
4. Одно изменение не должно автоматически менять другие категории.
5. Для спорных решений предусмотрен повторный review.
6. Пользователь должен видеть дату последнего обновления.

## Апелляции

Для апелляции пользователь указывает:

- категорию;
- текущий уровень;
- желаемое изменение;
- краткое объяснение;
- материалы для проверки.

## Что нужно уточнить перед запуском

- финальный список категорий;
- финальная шкала уровней;
- формат материалов для проверки;
- сроки review;
- состав reviewers;
- правила повторной апелляции.
