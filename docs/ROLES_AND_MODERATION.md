# CPVP.PRO roles and moderation

## Назначение

CPVP.PRO — расширяющееся Crystal PvP-комьюнити. TierList и тестирование являются важной частью платформы, но не единственным назначением сайта.

Этот документ фиксирует минимальную модель ролей для будущей реализации.

## Публичные роли

### Guest

Неавторизованный посетитель.

Доступ:

- просмотр публичных страниц;
- чтение гайдов;
- просмотр TierList;
- чтение форума;
- просмотр публичных профилей.

### Member

Авторизованный пользователь платформы.

Дополнительно доступно:

- настройка профиля;
- сохранение прогресса обучения;
- создание тем и ответов на форуме;
- отправка жалоб;
- получение уведомлений.

### Verified player

Пользователь с безопасно привязанным и подтверждённым лицензированным Minecraft Java Edition аккаунтом.

Дополнительно доступно:

- значок подтверждения;
- расширенная карточка профиля;
- участие в TierList;
- подача tier-test заявки;
- история изменений TierList.

## Tier testing roles

### Regular tester

Обычный тиртестер.

Требования:

- минимум `LT3` в категории `Vanilla`;
- пройти набор тестеров;
- быть одобренным staff;
- оставаться доверенным лицом проекта.

Обязанности:

- проводить low-tier тесты;
- по игре оценивать примерный тир заявителя;
- выдавать результат максимум до `LT3`;
- выявлять игроков, подходящих для бонусного HT3 skip-test;
- фиксировать результат и краткую причину.

### Senior tester

Старший тиртестер.

Senior tester не назначается автоматически каждому игроку с `HT3`.

Требования:

- уже быть regular tester;
- получить `HT3` или выше;
- быть отдельно предложенным на роль;
- подходить по доверию, стабильности решений и поведению;
- быть утверждённым staff.

Обязанности:

- проводить бонусные HT3 skip-tests;
- наблюдать high-tier матчи в spectator mode;
- смотреть полные записи матчей;
- быстро выносить verdict;
- участвовать в разборе спорных случаев.

### Staff

Staff управляет системой и принимает финальные решения в спорных случаях.

Доступ:

- добавление и удаление testers;
- назначение senior testers;
- разрешение разногласий между senior testers;
- управление правилами;
- просмотр журнала действий;
- управление модераторами;
- управление категориями платформы.

## Community moderation roles

### Moderator

Пользователь, который поддерживает порядок на платформе.

Доступ:

- обработка жалоб;
- скрытие нарушающего контента;
- предупреждения пользователям;
- модерация тем и ответов;
- просмотр очереди обращений.

### Administrator

Полный доступ к настройкам платформы.

Доступ:

- управление ролями;
- управление категориями;
- настройка правил;
- просмотр журнала действий;
- управление модераторами.

## Verdict rules

Для high-tier матча с записью:

1. Полную запись смотрят минимум два senior tester.
2. Если оба согласны, verdict принимается.
3. Если у senior testers разногласие, решение передаётся staff.
4. Решение и краткая причина сохраняются в истории.

## Принципы модерации

1. Каждое решение должно иметь понятную причину.
2. Изменения TierList должны сохраняться в истории.
3. Важные действия staff и модераторов должны попадать в журнал.
4. Жалобы должны иметь статусы `new`, `in_review`, `resolved`, `rejected`.
5. Пользователь должен понимать, почему его контент скрыт или изменён.
6. Удаление должно использоваться только там, где скрытия недостаточно.

## Минимальная очередь модерации

Для первой версии достаточно:

1. Жалобы на форум.
2. Tier-test заявки.
3. Проверка записей high-tier матчей.
4. Апелляции.
5. Журнал действий.
